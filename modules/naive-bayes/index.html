Build a Naive Bayes classifier

Start with a tiny labeled corpus. Calculate each parameter yourself, check your work, and then classify a new sentence. The default corpus is the Chinese/Beijing versus Tokyo/Japan example from the class slides.

What you will learn

The task: Each training sentence has a label. You will estimate how common each label is and how likely each word is within each label. Then you will use those estimates to predict the label of a new sentence.

The model: Multinomial Naive Bayes treats a sentence as a bag of words. It counts word occurrences but ignores word order. Its “naive” assumption is that word occurrences are conditionally independent given the class. Natural language does not always meet that assumption, but it makes the calculation manageable.

Predicted class = argmaxc P(c) × ∏word occurrences in test sentence P(word | c)

Bayes’ rule includes a denominator P(test sentence). It is the same for every candidate class, so you can omit it when choosing which class has the highest score. The resulting products are unnormalized scores.

Your route: Enter examples → count class priors → find vocabulary → total word tokens → count words by class → smooth the probabilities → score the test sentence. Enter fractions such as 3/4 or decimals. Every checkpoint accepts rounding to about two decimal places.

Key terms and an example of word order

A document is one labeled training sentence. A class is its label. A token is one occurrence of a word, so “Chinese Chinese” has two tokens. A type is a distinct word, so those two occurrences contribute one vocabulary type. Under the bag of words assumption, “dog bites man” and “man bites dog” have identical word counts, even though they mean different things.

Tokenization for this exercise: lowercase words; punctuation separates words; repetitions count. All training words stay in the vocabulary. Test words absent from training are ignored. The method follows the supplied LING 350 Naive Bayes slides; the slide example is the default corpus.
